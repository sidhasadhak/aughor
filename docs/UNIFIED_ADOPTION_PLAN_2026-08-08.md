## 1. The thesis

Aughor has three deficits, and the two studies turn out to be two halves of one answer:

1. **Knowledge the user gives us evaporates.** *[v2 — narrowed but standing:]* Since S3 (PR #271), an answer-level correction has a capture path — the fix-it flow records a typed what-was-wrong (+ optional corrected SQL) through `record_verdict` into the ambiguity ledger, and the next matching question cites it. What still evaporates is **structural** guidance: table routing ("use the view, not the base fact"), standing facts ("fiscal year starts in February") — no vocabulary, no enforcement point, no capture. *(Prime Agent's Continual Harness is the pattern: immutable base + supplemental structured facts + evidence + rollback.)*
2. **The conversation is owned by the pipeline.** Every message is force-compiled into an analysis program; the model is a subroutine. Users cannot brainstorm, steer, or ask meta-questions. *(Open-WebUI's inversion is the pattern: the model routes, the pipeline executes; capabilities live in docstrings; failures are values.)* *[v2: unchanged by #271 — the branch improved the bodies, not the door.]*
3. **The platform plumbing has known gaps** that Prime Agent solved: tests can reach paid LLM backends, interrupted work is indistinguishable from failed work, output caps are only model-shaped (not task-shaped), and background side-effects lack durable claims.

One direction unifies all three: **the model directs, deterministic code enforces, durable stores remember.** This is also aughor's own Track-A thesis ("we restrict intelligence instead of directing it") extended from model capability to conversation and memory.

## 2. Constraints and design principles

From aughor's recorded lessons (**C**) and the studies (**P**). Every layer below must satisfy all of them.

- **C1 — Serverless-first.** No resident processes; durable state in Postgres/YAML artifact stores/job rows. We adopt Prime Agent's *invariants*, never its daemon/kernel topology.
- **C2 — Deterministic guards beat LLM machinery** (NL2SQL conclusion, 4×). Enforcement is deterministic code; LLMs only propose, review, and *route conversation*. The R4 rule ("no LLM alone in the decision path") applies to **SQL correctness, not conversation routing** — this reframe is the keystone of Layer 3.
- **C3 — Flag-gate where a flag earns its keep** — **[v2, the endgame-doctrine form]**: the registry was just paid down 89 → 2, and the endgame's own findings decide what deserves a flag. A flag exists to de-risk an UNPROVEN behavior change with real cost or blast radius; a data gate is not a flag (Wave 2: "every gate became its data gate"); an off-path that tells a falsehood is not safety (Wave 4's test); budgets live in ModelProfile, not booleans (A1's founding job). Applied: **exactly TWO experiment loans** — `ask.converse` (new answer path, unmeasured routing, loop cost) and `harness.refine_gate` (recurring LLM spend, unproven proposal value) — each with its exit named in this document. Everything else ships hardwired: deterministic, additive-only, data-gated (empty store ⇒ byte-identical by construction), with the off-state proven by tests instead of guarded by a switch.
- **C4 — Human approval for durable writes.** Prime Agent auto-applies refinements with no review UI (its weakest point); we deliberately diverge: run-local notes may auto-apply, durable writes land as one-click proposals. *[v2 precedent shipped: the S3 fix-it verdict is itself the human act, and S5's cited memory made ledger writes visible and revocable — the review-and-revoke surface this constraint wants already has a home in the Memory panel.]*
- **C5 — Measure the premise before building.** Items marked **PRE-CHECK** start with instrumentation, not code (Wave-H record: six of six pre-checks moved their scope; the Wave-5 grids refused themselves the same way).
- **P1 — The model writes the last word.** Everything the pipeline does — success or failure — is narrated back to the model as context; the user never sees a raw system string.
- **P2 — Failures are values, not exceptions.** A failed stage produces worse context, not a dead turn.
- **P3 — Capabilities live in docstrings, not routers.** Gates are about *permission to offer* (license/RBAC/capability), never about message content. No intent classifier for tool selection, ever.
- **P4 — Background work never blocks and never errors visibly.** Every background LLM call has a deterministic non-LLM fallback. *[v2: the existing follow-up emissions already honor this — `tolerate`-wrapped, post-answer, never blocking.]*
- **P5 — Never disable the input; never destroy an answer.** Steering, queuing, and partial results are structural, not per-feature. *[v2: the second half is partially real — R4's error rendering already keeps the partial and only changes the tail.]*

**What we do NOT adopt** (from both studies): the IPython kernel / fork-server / dill machinery; resident agent-messaging daemons; auto-applied self-refinement; a big behavioral system prompt (Open-WebUI ships none); a full message-tree retrofit ahead of Track C's data-model decision.

## Layer 0 — Test & contract infrastructure *(build first; everything else gets cheaper)*

- `set_responses([...])` — scripted completions **or factories** `(system, user, role, model, call_index) → completion`. The factory form is the payoff: a test receives the exact prompt the code built (e.g. asserting Layer 1's schema annotations reached the prompt, or Layer 3's tool docstrings) and controls the reply.
- Exhausted queue → loud `FauxResponsesExhausted`, **never fallthrough** — the precise failure that bit the old fake (`tests/conftest.py:130`).
- Scriptable failure shapes the reliability layer classifies: truncation (`finish_reason="length"`), rate-limit, malformed JSON — making `aughor/llm/reliability.py`'s taxonomy testable offline.
- *[v2]* The faux backend must speak the **ModelProfile contract** too: it registers under a model id with a declared tier so `profile_for()`/`tier_for()` resolve deterministically in tests (PR-1's provider tests pin tier-dependent defaults via env — the faux backend gives them a cleaner seam).

**0.2 Mechanical no-key guarantee.** A conftest fixture (or `test.sh`-style wrapper) that unsets every provider credential and pins `AUGHOR_FALLBACK_BACKENDS=""`, with a session-start assertion — so the fallback chain *structurally cannot* reach a paid backend from a test (the `together`-had-a-key incident, made impossible). **0.3 Contract governance remainder.** CI already has the codegen-drift gate. Unchanged priority.]* *(Optional, only if drift recurs: a committed contract digest + `CONTRACT_REVISION` constant.)*

**0.4 Small wins** (≤ half a day each): `web/.npmrc` `min-release-age=7` (verify CI npm ≥ 11.10 — older npm silently ignores it); the tombstone principle recorded in engineering principles (*"reversing durable intent must clear the durable record before acting"*); one boundary ratchet (`aughor/ontology/*` must not import `aughor/llm` — keeps knowledge stores deterministic and hermetic; *[v2] the family precedent is fresh: #271's A4 added the executor↔agent boundary through a kernel seam after the existing ratchet rejected a direct import — same pattern, same test family*); a single shared wording for interrupted work (*"its result is uncertain and was not replayed"*).

## Layer 1 — Durable knowledge: the Continual Harness

The pattern (Prime Agent, adapted): **immutable base by construction** + supplemental structured store + bounded edit vocabulary + before/after snapshots + cheap review gate + **injection as a bounded index**. Aughor already independently built pieces: the override store's EXPLAIN-bind gate *is* "an entry must prove it's callable"; YAML-in-git *is* snapshot/rollback. *[v2 — two more pieces shipped in #271: the S3 fix-it flow is a live capture pattern for volunteered corrections (typed text + optional SQL + evidence → durable store → read back into planning), and S5's cited memory (`GET/DELETE /learning/resolutions`, Memory-panel rows with Revoke) is the visibility-and-rollback surface. The harness generalizes both from answer-level to structural knowledge.]* What's missing is the loop for **structural** guidance: capture → vocabulary → enforcement.

**1.1 Table-routing guidance** *(the found gap; chip `task_34d493b4` exists)*.
- **Vocabulary:** add `"use_instead"` to `_EDITABLE["entity"]` in `aughor/ontology/overrides.py` — value `{table, scope, reason}`, provenance and `source: human` inherited. Existence-bind on write (preferred table must exist in the schema; a typo stores `bound=False` and is never enforced). Heed the module's frozen-values warning: new *field*, not new kind — no directory migration.
- **Enforcement, deterministic, phased:** *(a)* retriever post-filter (`aughor/semantic/retriever.py`, after `_retrieve`): if a deprecated table survived top-k, **inject its preferred twin** into the keep-set — never silently drop the base table (scope matching is fuzzy; adding information is safe, removing is not); *(b)* schema-text annotation in the `apply_schema_enrichment`/`apply_glossary` pass: `⚠ prefer v_fact_sales for general sales calculations (human, 2026-08-08)` on the deprecated line, `✓ preferred…` on the view — *[v2] and the same annotation must survive `link_schema`: A3 made the linker rank-and-pack to the model's window, so the annotated pair must be kept **together** by the packer (add the preferred twin to the linker's keep-set exactly as in (a) — the retriever and the linker are two doors to the same prompt now, and enforcing at one while the other drops the view would be the both-ends-exist-feature-doesn't trap)*; *(c)* **phase 2, observe-only**: post-generation SQL check (deprecated table + lenient scope match → counter + answer-trace stamp; consider blocking only after real hit-rate data — C5).
- **Capture:** *[v2, re-based on shipped machinery]* two entry points, both landing in one review surface: **(i)** extend the clarify-crystallize pattern (`_apply_clarify_choice`) from *answers to our questions* to *volunteered corrections* — a `proposed_guidance` event with the structured fields + evidence (chat turn, run id); **(ii)** the **fix-it form** (S3) gains a "this is about which table to use" shape — when the typed correction names a table preference, offer it as a routing proposal instead of only a verdict note. The confirmation chip renders the before/after YAML diff; one click → the existing override endpoints. **Never auto-apply** (C4). Evidence must point at a run that exists (Wave-L rule). Proposals appear beside S5's remembered readings in the Memory panel — one place where the system's memory is inspected, confirmed, and revoked.
- **No flag** *(v2 SOTA call)*: enforcement is additive-only, deterministic, and DATA-gated — a connection with no `use_instead` overrides behaves byte-identically by construction, which is the off-switch the endgame taught us to trust (the Wave-2 hardwire pattern: an untagged securable behaves exactly as before). Durable writes stay human-click-gated (C4). Tests carry the guarantee: store round-trip, post-filter unit (no override ⇒ byte-identical), **linker keep-set unit** *(v2)*, annotation golden, capture endpoint, standard ratchet pass — all offline via Layer 0.

**1.2 Guidance notes** — durable connection-scoped facts with no ontology target ("fiscal year starts in February"). A new `note` TargetKind in the override store (`{title, content, scope_tags}`; frozen-values discipline applies), injected **Open-WebUI's two-band way**: notes are Band A — *always injected in full*, one-liners, bounded index (start N=6, 180 chars) — because relevance-gating a user's standing preferences is the classic amnesia mistake; retrieved context stays Band B with its own cap so it can never starve identity. No retrieval machinery until a connection exceeds ~20 notes (C5). Check first whether a candidate fact is already expressible (`exclude_when` covers "exclude test orgs"). *[v2: also check the ambiguity ledger — "always report EUR" may already be a crystallizable reading; a note kind must not become a second home for what the ledger owns. Rule of thumb: the ledger stores READINGS of ambiguous terms; notes store FACTS with no term to attach to.]* Shares 1.1's capture UI and its no-flag, data-gated posture (C3 v2): no notes stored ⇒ byte-identical.

> **[PRE-CHECK 2026-08-08 — do NOT build this as a new store.]** Both canonical examples already exist as `OrgSettings` fields (`currency_code`, `fiscal_year_start_month`), and fiscal year is not merely stated but **deterministically enforced** — `sql/fiscal.py` and `semantic/compiler.py` shift QUARTER/YEAR boundaries from the setting, so a note repeating it is a weaker second home for a fact that already has a compiler. `semantic/connection_kb.py` already declares a `note` kind carrying nearly the proposed shape; it differs only in being relevance-gated rather than always-injected. There is also no "Band A/B" budget mechanism anywhere — prompt blocks are unconditional concatenation; the closest precedent for an always-injected connection-scoped block is `render_exploration_annotations` via the schema-annotator registry.

**1.3 Post-run refine gate** — Prime Agent's auto-refine, adapted to batch: after an exploration/investigation with findings, one small-model call asks *"did this run surface a durable, evidenced lesson? Reject one-off noise, unsupported hypotheses, transient tool output."* Output: 0–3 **proposals** into 1.1's review inbox, `evidence = run_id` + trace excerpt. Flag `harness.refine_gate` — **EXPERIMENT; exit:** proposal acceptance rate ≥ ~30% over the first 20 proposals, else the gate is noise and dies.

## Layer 2 — Conversational aliveness *(no architectural change; every item lands inside today's modes)*

- **Artifact-aware specialization**: feed the generator the answer artifact (SQL, columns, filters, grain) so suggestions are *operations on the current result* — "break this out by region", "same view, trailing 12 months", "what's driving the Q3 dip". Aughor's advantage over generic chat, currently unused (the deep site sends only question + headline).
- **One template + one slot**: unify the four sites onto a single overridable template on the task-model slot with fallback-to-chat-model.

**2.2 Narrated failures — [v2: the emission half SHIPPED; this is the narration half].** A4 (#271) made every silent rewrite emit a `guard_receipt` frame, and B2 renders them as Chain-of-Thought steps — "restriction becomes visible direction" is live **in the UI**. ## Layer 3 — The converse body *(the architectural move — unchanged in substance by #271, strengthened at three joints)*

A third body behind `/ask`: **`_stream_converse`** — a real agent turn whose tools wrap the existing guarded machinery. **The guards stay inside the tools; the model decides which tool the conversation needs — including the tool of just answering.**

| Tool | Wraps | Notes *[v2 where changed]* |
|---|---|---|
| `answer_question(question)` | today's quick body, whole | the full guarded pipeline as one call |
| `start_investigation(question, mode)` | today's deep body | **admission handle** (Prime Agent's pattern): returns immediately, streams into the turn; never blocks the conversation on completion. Converse turns pass `allow_clarify=false` by construction — a headless caller property, exactly what the Wave-2 dissolution built |
| `list_tables()` / `describe_table(name)` / `sample(name)` | catalog/schema stores | progressive disclosure: schema enters as a *manifest*, detail on demand. *[v2: A2 head samples ship in every connector's schema now — `describe_table` returns the self-describing column lines for free]* |
| `run_sql(sql)` | the guarded execute chokepoint | every existing guard fires inside; *[v2: the guards now EMIT — preflight/de-fan receipts flow through the kernel seam, so the tool returns `{result, guard_receipts}` and the model narrates real events, not reconstructions. P1/P2's data source is already built]* |
| `search_history(query)` | findings/briefings/trusted queries | "have we looked at this before?" |
| `save_guidance(...)` | Layer 1 capture | corrections offered mid-conversation become one-click proposals |
| `ask_user(question, options?)` | Layer 2.3 surface | clarify becomes a tool the model chooses, not a gate |

Rules of the body: docstrings are the routing policy (P3 — no intent classifier); tool availability is permission-gated, never content-gated; **minimal system prompt** — connection identity, schema manifest, guidance-notes index (Layer 1.2 Band A), verified semantic layer: *state, not instructions*; failures are values (P2); a real loop budget, every iteration streamed through the existing SSE surface. *[v2: budgets and parallelism come from ModelProfile — the loop cap is `profile_for("coder")`-derived, not a new constant; the free-tier RPM math (risk 2) reads `rpm_budget` from the same profile.]*

**Routing inverts gradually.** The deterministic spine survives as the **fast path**: clear, well-formed analytical asks still go straight to quick/deep with zero extra hops (latency and the R4 lesson preserved; this is Open-WebUI's `legacy` mode kept as a per-request optimization). Everything else — vague, meta, exploratory, brainstormy — lands in converse instead of being force-compiled. The route receipt measures the converse/fast-path ratio and tells us when converse should become the default door.

Flag `ask.converse` — **EXPERIMENT; exit:** the §5 headline receipt (the 10-turn session) plus the parity invariant; graduation = converse becomes a permanent third body and the flag dies (endgame policy). Quick/deep bodies untouched — they gain a caller. **Invariant to assert** (graduation receipt): converse-wrapped `answer_question` and the direct fast path produce identical answers for identical questions.

*[v2 relationship to Track C]*: Layer 3 lands on the **existing** web shell first (the chat surface already renders every frame converse emits). Track C's chatbot shell (C2–C4) then adopts converse as its brain — the C1 adapter already proved the SSE→UIMessage mapping. Track C does not block Layer 3; Layer 3 de-risks Track C.

## Layer 4 — Platform robustness & cost *(independent of Layers 1–3; schedule in parallel)*

**4.1 Scheduler & jobs honesty** (Prime Agent). *[v2 re-base — the anatomy changed in #271:]* the legacy per-object schedulers are DELETED; monitors and briefs ride the one automation-engine tick as virtual automations, `/cron/tick` delegates to `tick_once()`, and due-ness is the engine's since-last-run check. The gaps, restated against the new anatomy: *(a)* **PRE-CHECK** — do side-effectful deliveries (brief sends inside the `brief` effect; webhook/notification dispatches) have per-item, per-period dedup, or can an engine tick crashing mid-delivery double-send on the next tick? The claim row, if needed, attaches at the effect dispatch in `automations/engine.py` — written in the same durable write that records the run, before the send; a dangling claim marks `uncertain`, never re-sends in-period. *(b)* Distinct terminal status `interrupted_uncertain` (vs `failed`) in `kernel/jobs.py` — "it broke" and "we don't know how far it got" are different facts; the lease machinery (#265) and the `job.foreign` event give it clean semantics. *(c)* **Recovery markers in agent context**: when an exploration slice's lease is reclaimed stale, the next slice's prompt carries *"previous slice was interrupted mid-work (uncertain); verify recorded findings before repeating them"* — Prime Agent tells the model its own history has a gap; this directly prevents duplicate findings. **No flag** *(v2 SOTA call)*: labeling interrupted work `failed` is a FALSEHOOD, not a safe default — an off-path that lies fails Wave 4's test ("does the off-path merely skip work?"). b+c ship hardwired with tests (the marker is the same fact reaching a second reader, not a second feature); (a) is PRE-CHECK-gated and, if built, is a correctness fix, not an experiment.

**4.2 Output budgets — [v2: half shipped].** ModelProfile (#271) already replaced the flat constant: `_max_output_tokens()` resolves through `tier_for()` (baseline 4096 / capable 8192), env override wins, unknown model ⇒ baseline (Prime Agent's never-regress rule, already honored). Remaining: *(a)* **role-shaping**: `profile_for(role)` already takes the role; add per-role output caps to the tiers — synthesis/briefing up to 16k on capable models, judge/gate 1k, default unchanged. Implement IN ModelProfile (the keystone absorbs capability knobs so they don't come back as constants — its founding job). *(b)* **Reduce-and-recompose for briefings**: on `TRUNCATED` in briefing synthesis, partition the findings and synthesize in parts + merge — the compaction-shaped answer to a truncation retries can't fix (the ~25-finding briefing death is only softened by 8192, not solved). *(c)* **PRE-CHECK** `aughor/agent/evidence_budget.py` accounting: exclude cache-read tokens from any loop budget. **No new flag** for (a) — it's a ModelProfile tier field like the rest; (b) is failure-path-only (byte-identical on success) and ships flagless with its own tests.

**4.3 Result handles + inventory re-injection — PRE-CHECK first.** Prime Agent's best context trick (results live outside context as named handles; post-compaction, the live-handle inventory is re-injected so the model reuses instead of recomputing) matched to aughor's own "pass a REFERENCE" spike lesson. **Do the measurement only**: extend `kernel/metering.py` with chars-of-tool-results-injected-per-prompt and repeated-identical-query counts per exploration; read the data. If low — stop; the workstream dissolves. If warranted: per-exploration handle registry (`{handle_id, sql_hash, materialization, schema, row_count, preview}`), prompts carry handle + preview, slice-start injects the inventory. Note: Layer 3's `run_sql`/`describe_table` tools are natural handle producers — design them handle-shaped from day one so 4.3 slots in without rework.

## Layer 5 — Frontend steerability *(merges into Tracks B/C; backend hooks listed here)*

In effect-per-work order (Open-WebUI frontend study), *[v2 status against #271]*:
1. **The input is never disabled** (P5): typing while an answer streams queues the message — visible, editable, deletable — or interrupts; user's choice. Backend needs only a stop endpoint per run. *[Still open — the composer still sets `disabled={streaming}`.]*
2. **Partial answers survive** stop/error/reload. *[Half shipped: R4's error state already renders below the partial ("a failed turn keeps what it produced; only the tail changes"). Remainder: flush partials `done=true` on cancel, and reconnect-reconciliation ("is this chat still generating?").]*
3. **Guided regeneration**: "Suggest a change" + canned steers ("more concise", "add detail"); backend accepts `regeneration_prompt` appended as a trailing user turn **with the rejected answer kept in context** so the model knows what to avoid — zero-typing course correction. *[Open. Note the S3 fix-it form is the CORRECTNESS sibling (records a verdict); guided regen is the STYLE sibling (records nothing durable) — keep them distinct affordances.]*
4. Follow-up chips (2.1's upgrade), status timeline *(shipped — 2.4)*, Escape-as-reset, ArrowUp-to-edit-last — small, high-feel.
5. **Defer the message tree** (append-never-overwrite branching). It's Open-WebUI's deepest mechanic and nearly impossible to retrofit later — which is exactly why it must be decided as part of Track C's chat data model, not bolted on here. Until then, non-destructive regeneration (keep the old answer addressable) is the 20% that matters.
